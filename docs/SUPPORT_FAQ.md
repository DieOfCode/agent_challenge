# Support FAQ

## Авторизация: invalid_grant / AUTH_401

Симптом:
- Пользователь не может войти после смены или сброса пароля.

Быстрая проверка:
1. Убедиться, что пользователь входит с актуальным email.
2. Сбросить активные сессии (logout all sessions).
3. Проверить время на устройстве пользователя (сильный дрифт времени ломает токены).
4. Проверить ограничение на число попыток входа.

Решение:
- Принудительно завершить старые сессии.
- Инициировать новый reset password.
- Если ошибка сохраняется, запросить `request_id` и время попытки для проверки в auth-логах.

## 2FA: код не приходит / AUTH_2FA_TIMEOUT

Симптом:
- SMS или email-код подтверждения приходит с задержкой либо не приходит.

Быстрая проверка:
1. Уточнить страну и оператора пользователя.
2. Проверить лимиты отправки и блокировки на стороне провайдера.
3. Предложить fallback на email-код.

Решение:
- Переключить метод 2FA на fallback.
- Повторить отправку спустя 60 секунд.
- При повторе проблемы эскалировать в канал infra-auth.

## SSO: ошибка подписи токена / SSO_403

Симптом:
- Корпоративный пользователь не может войти по SSO.

Быстрая проверка:
1. Проверить валидность сертификата IdP.
2. Проверить audience/issuer и clock skew.
3. Проверить ротацию ключей и кэш jwks.

Решение:
- Обновить конфигурацию IdP в проекте.
- Сбросить кэш ключей SSO.
- Провести тест входа на отдельном пользователе.

## Dashboard: chunk_load_error / UI_3001

Симптом:
- После входа пользователь видит белый экран.

Быстрая проверка:
1. Очистить кеш браузера (hard reload).
2. Проверить версию frontend bundle.
3. Проверить CDN-инвалидацию.

Решение:
- Попросить пользователя перезайти после hard reload.
- Если не помогло, включить fallback bundle и проверить deploy rollout.
